Features

Everything happens
on your machine.

No API keys, no cloud dependency. A complete vision agent that runs where your data already lives.

On-device VLM

A quantized vision model runs in the browser on WebGPU. No server, no API — just local inference.

PII auto-redaction

Passwords, card numbers, OTPs — detected by Luhn/Verhoeff rules and scrubbed before serialisation.

Canvas redaction

Sensitive page regions are black-boxed on the canvas before any screenshot leaves the local context.

DOM scrubbing

Fields are stripped of values, URLs lose query strings, and free text runs through PII redaction.

Keyword ranker

Deterministic synonym ranker grounds prompts, corroborates model output, and plans when the VLM can't.

WebGPU accelerated

Per-graph quantization — embeddings stay fp16 while encoder and decoder run at q4 for speed.

Architecture

Three tiers.
Most private path first.

The agent tries local inference first and only escalates when it genuinely needs help — with redacted data.

TIER 1

Local VLM + Ranker

The on-device VLM reads the screenshot and scrubbed DOM, plans an action, and the keyword ranker corroborates. Agreement raises confidence. Zero network calls.

Fully on-device — nothing leaves Chrome
TIER 2

Ranker-only fallback

If the VLM produces nothing usable, the keyword ranker plans the action alone using the already-scrubbed DOM. Still fully local.

Local fallback — still no network
TIER 3

Redacted escalation

Last resort. A canvas-redacted screenshot and scrubbed DOM are sent to a local or remote VLM. The server returns a structural command — private values are re-hydrated locally.

Server never sees raw data
Privacy

Your data.
Your device.

Privacy isn't a feature we added — it's how the architecture works.

◻️

Raw frames stay local

Unredacted screenshots only reach the offscreen WebGPU worker. The WebSocket client receives only canvas-redacted output.

🔑

Credentials never serialised

Passwords, CVVs, OTPs, and card numbers are stripped at the DOM scrubber — they never enter any payload.

🔗

URLs stripped of tokens

Only origin + pathname is kept. Auth tokens and tracking params in query strings are dropped.

🚫

Server can't exfiltrate

The hydrator refuses USER_PASSWORD and OTP_CODE. A compromised server cannot make the extension type a credential.

Get started

Running in four steps.

From clone to your first AI-assisted action — no cloud keys required.

01

Clone & install

Clone the repo and run npm install at the workspace root.

02

Build extension

Run npm run dev:client to build into client/dist with HMR.

03

Load in Chrome

chrome://extensions → Developer Mode → Load Unpacked → select client/dist.

04

Set a goal

Click the extension, type a goal like "Accept cookies", and hit Run.
